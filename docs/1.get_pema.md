PEMA is a [Nextflow](https://www.nextflow.io/) pipeline: every step runs in its own container, which Nextflow downloads the first time it is needed.
So you only need two things on your computer, server or cluster.


## 1. Nextflow

PEMA needs **Nextflow 25.04 or later**, which itself needs Java 17 or later.
Follow the [Nextflow installation instructions](https://www.nextflow.io/docs/latest/install.html), for example:

```
curl -s https://get.nextflow.io | bash
chmod +x nextflow
mv nextflow ~/bin/      # or any folder in your PATH
nextflow -version
```


## 2. A container engine

One of:

* [Docker](https://docs.docker.com/get-docker/), the default; the usual choice on a personal computer
* [Singularity](https://docs.sylabs.io/) or [Apptainer](https://apptainer.org/), the usual choice on HPC systems and shared servers
  (see [Running on HPC]({{ '/3.running_on_HPC/' | relative_url }}))
* [Podman](https://podman.io/)

> **Hint!** <br/>
On Windows and macOS, Docker Desktop has a memory (RAM) limit you might need to raise in its settings,
especially for the taxonomy assignment of COI data.


## 3. PEMA

Get the PEMA code from GitHub:

```
git clone https://github.com/hariszaf/pema.git
cd pema
```

> The Nextflow-based PEMA is developed on the `nf` branch; until it is released, run `git checkout nf` after cloning.

That's all: the containers (fastp, VSEARCH, Swarm, crest4, RDPClassifier, ...) are pulled automatically when you first run PEMA.
The reference databases are downloaded the first time they are used, too.

You are ready to set up your analysis; see [Basics for running PEMA]({{ '/2.running_general/' | relative_url }}).


## Checking your setup

The PEMA repository includes a sanity check: it downloads a small dataset (16S, 18S, 12S, COI and ITS samples) and runs PEMA on it.
It is a good way to check that everything works on your machine, and to see what PEMA returns:

```
sanity_check/run_sanity_check.sh 16S
```

Run `sanity_check/run_sanity_check.sh --help` to see all the tests.
